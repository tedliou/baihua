PASS if 開頭先寫讀者的情境與風險（讓 Agent 自己 commit 與推送、可能直接推送 main 或 force-push），再寫只把規則寫給 Agent 看不夠的原因，接著寫 hook 在指令執行前檢查、判定擋下就不執行；判斷句都有主詞、動作與後果；第二段保留私有 repo、付費方案、免費組織帳號、draft → PR → main 的流程，並寫出人在終端機手動推送不受影響。
FAIL if 第一句直接寫 hook 的機制或規則不夠，沒有先交代情境；仍有壓成片語、要讀者自己補主詞的句子；刪掉付費方案連結、權限模式、子代理等事實；或加入原文沒有的功能。連接詞與被動句不扣分。
