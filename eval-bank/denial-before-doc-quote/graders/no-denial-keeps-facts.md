原文的第二段是「這裡先不要把它想成背景畫面設定。這次要確認的是，瀏覽器被打開之後，Unity 還會不會繼續處理 Callback。」第三段說官方文件「對這個選項講得很直接」。
前一句先否定一個讀者原本沒有的誤解，「講得很直接」是評價詞，兩者都沒有提供資訊。
PASS if 「先不要把它想成背景畫面設定」這類否定句不見了（可以直接說明這個選項決定什麼，或直接引用官方說明），「講得很直接」這類評價詞也不見了，並且原樣保留選單路徑、程式碼區塊與官方文件連結，說明了 Windows Player 的這個行為由「Run In Background」控制、啟用時失去焦點仍在背景執行、關閉時失去焦點就暫停。「這次要確認的是瀏覽器被打開之後 Unity 還會不會繼續處理 Callback」這層意思可以保留、併入其他句子，或刪除。
FAIL if 否定句或「講得很直接」仍在、刪掉路徑、連結或官方說明的兩種行為任一項、改動路徑或連結文字，或加入原文沒有的事實。
