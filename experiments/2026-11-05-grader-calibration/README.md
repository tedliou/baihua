# 評分條件校準

2026-11-05。題庫的評分條件要和作者的判斷一致，分數才有意義。這裡用作者審閱過的改寫結果，比較幾種評分條件和作者判斷的一致率。

## 資料

- 第一輪：`experiments/2026-11-04-rewrite-review/` 的 33 份輸出，作者逐題判通過或不通過（22 題通過、11 題不通過）。
- 第二輪：`experiments/2026-11-05-rewrite-review-r2/` 的 33 份輸出。作者快速看過，說沒有明顯的錯誤，只有 `lede-rules-not-enough-compressed` 的「判斷錯」過於口語，所以標成這題不通過、其餘通過。這輪的標記比較粗。

## 結果

| 評分條件 | 第一輪一致 | 兩輪合計一致 |
| --- | --- | --- |
| 各題原本的 llm 條件加 regex（`judge.py`，結果 `r1-v1.json`） | 15/33 | 未測 |
| 共用評分表第 1 版加 regex（`judge2.py`，`rubric-v1.json`） | 25/33 | 51/66 |
| 共用評分表第 2 版加放寬後的 regex（`rubric-v2.json`，評分表 `rubric-v2.md`） | 30/33 | 58/66 |

- 各題原本的 llm 條件是依推測寫的，多半比作者嚴：作者接受「先寫問題、再寫步驟」的順序與「由於……」這類連接詞，條件卻判不通過。
- 第 1 版評分表整理自作者在審閱裡的意見。第 2 版補上作者要求的兩點：標題的結果用正面說法、段落開頭要有交代情境的引導詞；並放寬三條比作者嚴的 regex（`argumentative-section-flow` 的「最簡單」、`filename-in-title-summary` 的 `models`、`ui-colon-label-item-descriptions` 的「附魔」）。
- 第 2 版仍不一致的 8 筆裡，第二輪有 5 筆的輸出留著作者在第一輪明確退回過的同一種問題（指導讀者的句子、描述式的標題、「沒有實測」），作者快速瀏覽時判了通過。這幾筆比較像標記的誤差，評分表的判斷和作者第一輪的標準一致。

評審模型用 Sonnet，每份輸出投 3 票取多數。第 2 版評分表放進 `eval-bank/_common/graders/author-rubric.md`，套用到每一題。
