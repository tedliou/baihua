這份評分表整理自作者審閱改寫結果時的判斷。標準是：作者讀過之後，願意直接把它放進自己的技術文章、文件或介面，不必再改。只有明顯的問題才判 FAIL，留下一兩個不影響閱讀的小用字不算。

FAIL if 輸出有下列任一個明顯的問題：
1. 還有在指導或教育讀者的句子，例如「先不要把它想成……」「分清楚它們才用得好」，或恭維、裝熟的語氣。
2. 過於口語或詞被截短，不適合放進文章，例如「字都寫對」（應為「生成的文字都正確」）、「判斷錯」（應為「判斷錯誤」）。
3. 句子缺主詞、受詞或必要的引導詞，讀者要自己補關係，例如「我的兩個專案各放一份」沒寫出是誰放了什麼；段落開頭突然丟出一個事實，少了「目前」這類交代情境的引導詞；因果關係只用逗號串起來，少了「由於……所以」。
4. 標題寫成一句說明怎麼做的話（例如「用 A 把 B 放進 C，開啟 D 前先確認 E」），或結果用否定說法（例如「不必每套各下載一次」），而不是「主題：讀者得到的結果」的形式。
5. 文章的開頭或 summary 直接切入做法或規格，沒有先交代讀者的問題或動機，再寫目的。這一條只適用於輸出包含文章開頭或 summary 的時候。
6. 留著作者沒做過的情境或「沒有實測」這類範圍聲明。
7. 刪掉或改動任務裡要求保留的事實、數字、連結或程式碼，或明顯捏造了原文沒有的事實。

PASS if 以上問題都沒有。下列情況不算問題，不要因此判 FAIL：用了「由於、因此、而」這類書面連接詞或被動句；留著一兩句輕微的評語；句子長短或用詞和你自己會寫的不同；段落順序是先寫問題、再寫做法。
