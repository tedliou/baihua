# 人工盲測：改寫題的逐步調整

2026-10-30。作者親自盲測，每輪 4 題，只問「哪一份比較通順」，選項是 A、B 與差不多。A、B 的順序由程式隨機決定，對照表在 `rounds/r*-key.json`，作者作答後才解開。拿給作者看之前，先用程式確認兩份都保留了原文的事實，兩份相似度超過 0.9 的配對直接算平手、不出題。

產生文字的方式和 [2026-10-30-syntax](../2026-10-30-syntax/README.md) 相同：Sonnet，不給工具，SKILL.md 全文附在系統提示，腳本也共用那裡的 `scripts/gen.py`。

## 判斷

- cand 不採用。它讓模型自己補上原文沒有的說明，例如「不會被多餘的功能分散注意力」，句子也變長。
- 第 3 輪的輸贏依文類分開：店家介紹與更新說明是 skill 贏，沒有 skill 的版本用了驚嘆號與推銷口吻。遊記與讀書心得是沒有 skill 的版本贏，它保留了「真的覺得大自然很厲害」這類口語感受。原因推測是核心規則 4「用具體事實取代評價」把心得裡的感受也當成沒有依據的評價。
- cand2 採用，但證據不強。4 比 3 不顯著，輸贏又幾乎由題目決定：觀影與食記兩次都是 cand2 贏，登山兩次都是 cur 贏。登山題 cand2 輸的原因是刪掉了「日出很壯闊」這類景色描寫，和這次修改要處理的問題無關。採用的理由是修改範圍窄，只影響個人心得，而且和第 3 輪的結果方向一致。之後若有反例再改回來。
- cand3 採用。改寫時把「令人屏息的湛藍海景」這類形容換成平實的描寫，但景色、味道、場面本身留下。這是登山題暴露的問題，用沒出現過的 4 題驗證，作者沒有一次選舊版。潤稿題的改動幅度和舊版相同，沒有退化。
- 第 8 輪換到英譯中與寫作，沒有 skill 的版本贏了歡迎信翻譯與客戶延期信。作者選的版本稱「您」、句子完整，保留了「敬請見諒」「謝謝您的理解」這類書信禮貌。skill 版改用「你」，語氣像同事間的訊息，翻譯時還加了原文沒有的「試用起來會更有感」。推測原因是語域表沒有「給客戶的信」，模型把它當成工作報告或介面文字。
- cand4 採用。正式文件語域加上給客戶或使用者的信件，要求保留問候、致歉與致謝，核心規則 10 也加上翻譯時不加原文沒有的評語。第 10 輪三題都判差不多，兩輪合計 3 勝 1 負、平手 4，沒有退化的跡象。
- 介面文字整體和沒有 skill 的版本差不多。skill 贏在 toast 與設定開關，句子完整、不用「僅」這類書面字。唯一兩次都輸的是相機權限說明：標題寫「允許使用相機」，內文又補一句「所以需要使用相機」，同一件事說了兩次。
- cand5 不採用。在介面文字語域明寫「標題已經說的事，內文不再說一次」，但驗證的 4 題裡，舊版也沒有出現重複，8 組有 5 組判平手，看不出效果。為了不加長 SKILL.md，先不放進去。

## 學到的事

- 作者偏好短而口語的版本，但不接受補上原文沒有的內容。
- 模型評審認為「改寫題輸給沒有 skill 的版本」，作者的判斷只在心得類成立，說明文類反而是 skill 贏。模型評審的結論要經過人工確認。
