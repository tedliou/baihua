# 語域：參考文件

讀者是來查一條規則、一個設定、一個指令或一個名詞的人，通常已經在使用產品，只想找到答案就離開。wiki、說明頁、API 文件、README、FAQ 都用這個語域。

## 讀者與口吻

- 像熟悉系統的同事在旁邊說明，平實、肯定，不寫成說明書或教學講義。
- 主詞以系統裡的東西為主（設定、指令、這個欄位）。讀者的動作用省略主詞的句子：`在設定頁打開「自動儲存」。`
- 少用「你」，不用「我們」，因為參考文件沒有作者陪讀者走的過程。
- 不提醒、不說教、不推銷，直接寫規則與結果。

## 開頭

- 每一頁或每一個條目的第一句寫出它是什麼、用來做什麼。
- 前：`本頁將介紹快取設定的相關選項。`
- 後：`快取設定決定頁面在瀏覽器裡保留多久，預設是 10 分鐘。`

## 內容

- 只寫目前版本的事實。不寫還沒做的功能、改版歷史與規劃，除非這一頁本來就是更新紀錄。
- 同一個資訊只在一個地方寫完整，其他地方用連結指過去。
- 數字、預設值與限制寫在最靠近的位置，不要散落在不同段落。
- 有條件的規則寫出條件：`只有管理員能刪除專案。`
- 建議要有情境與做法，不寫「多多嘗試」「找出最適合自己的方式」。

## 結構

- 段落短，每段集中一件事。建議每段三句以內，這是經驗值，不是硬性規定。
- 欄位、選項、參數用表格，表頭寫名詞（「名稱」「預設值」「用途」）。
- 步驟用編號清單，一步一個動作。
- 標題與表頭不用「用於」「取得自」這類直譯片語，改用「用途」「來源」。

## README

README 是參考文件的特例，讀者想在一分鐘內知道這是什麼、能不能用、怎麼開始。

- 第一段寫出專案做什麼、解決誰的問題。
- 接著是安裝與最小可執行的範例。
- 不用 emoji 當小標，不放和使用無關的徽章牆。
