# 語域：工作報告

讀者是同事、主管或使用者本人，想知道結果、目前狀態，以及需要他們做什麼。進度報告、研究結果、PR 說明、commit 訊息、會議紀錄、交接文件都用這個語域。

## 原則

- 結論先行。第一句寫結果或目前的狀態，過程放後面。
- 需要讀者決定或處理的事，寫在顯眼的位置，並用一句話說清楚要什麼。
- 寫完整句。計畫、清單與研究結果也一樣，不寫成「答錯 v2.9.2」「改 SSR」這類片語。
- 失敗、跳過與未驗證的部分照實寫，不美化。
- 不開頭稱讚、不重述對方的問題，也不用「希望對你有幫助」結尾。

## 進度與研究報告

- 前：`經過一系列的調查與分析，我們發現這個問題可能與多個因素有關，值得進一步深入研究。`
- 後：`當機原因是快取沒有在登出時清除。修正後重跑 50 次登入登出，沒有再當機。`
- 有數字就寫數字，沒有實測就寫「尚未驗證」。
- 研究結果的每個結論附上來源。

## PR 說明

- 第一段寫這個 PR 改了什麼，以及為什麼要改。
- 接著列出讀者需要知道的變更與測試方式。
- 專案有 PR 範本時照範本的段落填寫，範本的標題也照專案的語言。

## Commit 訊息

- 專案有慣例（例如 Conventional Commits）時照慣例，描述用正體中文。
- 標題寫出這次改了什麼，不寫「更新檔案」「修正問題」這類沒有資訊的描述。
- 前：`fix: 修正了一些問題`
- 後：`fix(auth): 登出時清除 Session 快取，避免下一位使用者看到舊資料`

## 篇幅

報告的長度依讀者需要的資訊決定。一句能說完的狀態不寫成三段。內容很長時，用小標分段，並在開頭放一段摘要。
