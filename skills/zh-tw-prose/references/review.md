# 編修與審稿

寫作者看過太多草稿，很難發現跨段重複、冗句與語氣不一致。同時處理內容、結構與句子時，也顧不到所有規則。所以長文與要對外發佈的文字寫完初稿後，交給沒有看過寫作過程的子代理，一次只負責一個層面：

```
初稿 → 結構編輯 → 文風編輯 → 審稿 → 寫作者依審稿意見修一輪 → 交稿
        章節、重複    逐句       只讀不改
        範圍、小標
   兩個編輯交回稿件時跑 check.py --compare：事實有沒有消失、句子有沒有被壓短
```

先改結構、再改句子，是因為句子改好以後整段被刪或搬走，那些修改就白做了。這個流程取自 vervecode.dev 的編修流水線。作者在 2026 年 9 到 11 月退回的問題，大多在當時已經寫成規則，只是起稿時沒有套用。拆成三步以後的第一篇新文章，作者交稿後只改了標題、開頭的一段與總結的一句。

## 何時跑哪幾步

| 情況 | 跑哪幾步 |
| --- | --- |
| 新的長文、整篇改寫的初稿 | 結構、文風、審稿，依審稿意見各修一輪 |
| 潤稿一兩段，不動章節與段落順序 | 只跑文風編輯，寫明只改哪幾段 |
| 使用者要求審稿 | 只跑審稿 |
| 一個段落以內的短文、介面字串 | 不需要，寫作者自己對照檢查清單 |

## brief

結構編輯與文風編輯拿完整的 brief，審稿只拿前三欄。brief 保存的是只存在寫作者對話裡的決定，交接時最容易丟掉的就是這些。

```text
讀者與讀者任務：
語域：（技術文章、參考文件、介面文字）
專案文風檔與用詞表：（路徑，沒有就寫「無」）
範圍外：
不能改的內容：數字、指令、設定值、版本、連結與截圖，再加上這篇特有的
作者手改過的句子：（逐句列出，沒有就寫「無」）
已核可的小標：（沒有就寫「無」）
篇幅參考：（同類文章的字數範圍，沒有就寫「無」）
```

## 步驟

每一步都等前一步完成才開始，因為兩個編輯同時改同一份稿件會互相覆寫。

- 子代理看不到這段對話，委派時把 brief 全文寫進交辦的訊息，不只寫「照 brief」。
- 從 plugin 安裝時，子代理的完整名稱是 `baihua:zh-tw-structure-editor`、`baihua:zh-tw-style-editor` 與 `baihua:zh-tw-reviewer`。
- 下面的 `check.py` 是本 skill 的 `scripts/check.py`。子代理複製檔案或執行 check.py 時，Claude Code 可能會請使用者同意，常用的話可以在專案設定加上允許規則。

1. 起稿完成後跑 `check.py <稿件>`，寫 brief。
2. 把稿件複製到系統暫存資料夾，當成「初稿備份」。交給 `zh-tw-structure-editor`，給它稿件路徑、初稿備份的路徑與 brief。它交回前會跑 `check.py --compare <初稿備份> <稿件> --stage structure`，回來後看它的改動紀錄與交接檢查，確認刪掉的事實都有理由。
3. 再把稿件複製一份，當成「結構後備份」。交給 `zh-tw-style-editor`，給它稿件路徑、結構後備份的路徑、brief，以及結構編輯回報裡「句子問題」那幾行。它交回前會跑 `--stage style` 的交接檢查。
4. 交給 `zh-tw-reviewer`，只給稿件路徑與 brief 的前三欄，不給改動紀錄。
5. 逐項判斷審稿意見：
   - 不是每一項都要照改，審稿者不知道的背景以寫作者掌握的事實為準。
   - 結構問題交回結構編輯，句子問題交回文風編輯，先結構後文風，各一次。
   - 修正後仍有的問題列給使用者，不再多跑一輪。
6. 跑 `check.py --compare <初稿備份> <稿件>`，看整個流程刪掉了哪些事實、虛詞密度怎麼變。再由寫作者自己讀完全文，寫作者是唯一知道討論脈絡的人，不能只轉送子代理的結果。

交接檢查的旗標。`fact-added` 與 `structure-changed` 只在 `--stage style` 時檢查：

| 旗標 | 意思 | 處理 |
| --- | --- | --- |
| `fact-removed` | 程式碼、網址、圖片或數字消失 | 結構編輯要說得出刪除理由，文風編輯一項都不能少 |
| `fact-added` | 只改句子時新增了數字或連結 | 確認不是補上素材沒有的事實 |
| `structure-changed` | 只改句子時動到小標或表格的數量 | 改回，把問題交給結構編輯 |
| `glue-drop` | 虛詞密度下降超過 5% | 句子被壓短，補回完整句 |
| `glue-rise` | 虛詞密度上升超過兩成 | 檢查連接詞有沒有補過頭 |

## 沒有安裝 plugin 時

在其他環境，把下面的範本貼給一般子代理，或貼到新對話，讓它只做審稿。只給檔案路徑或全文、讀者是誰，以及使用的語域。不要附上自己對稿件的判斷，也不要說哪裡已經改過，否則審稿者會被帶著走。

```text
請審閱這份正體中文稿件，只回報問題，不要修改檔案。

稿件：<路徑或全文>
讀者與讀者任務：<誰、要完成什麼>
語域：<技術文章、參考文件、介面文字之一>
專案文風檔與用詞表：<路徑，沒有就寫「無」>

先讀 zh-tw-prose skill 的 SKILL.md、patterns.md、translationese.md、taiwan-usage.md、
punctuation.md、integrity.md，以及對應語域的檔案。專案有文風檔與用詞表時一併讀。

冗長與過度縮寫兩個方向都要查。只列有問題的地方，依影響排序：先是讀者任務與事實，
其次是結構與重複，最後是句子、用詞與標點。每個問題一行，格式如下：

<位置（行號或引用原句的前幾個字）>｜<負責的步驟：結構／文風／事實／作者>｜<問題>｜<建議寫法>

沒有把握的標「不確定」。需要作者提供事實才能改的，標「待作者補充」。
最後用兩三句說明這份稿件是否服務它的讀者。不稱讚，不重述規則。
```
