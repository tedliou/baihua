# 審稿

寫作者看過太多草稿，很難發現跨段重複、冗句與語氣不一致。只讀一次全文的審稿者比較容易看出這些問題，所以長文與要對外發佈的文字，交給沒有看過寫作過程的審稿者。

## 交辦方式

- 在 Claude Code 安裝了本 plugin 時，交給 `zh-tw-reviewer` 子代理。
- 其他環境可以交給一般的子代理，或開一個新的對話，把下面的範本貼過去。
- 只給檔案路徑或全文、讀者是誰，以及使用的語域。不要附上自己對稿件的判斷，也不要說哪裡已經改過，否則審稿者會被帶著走。

## 範本

```text
請審閱這份正體中文稿件，只回報問題，不要修改檔案。

稿件：<路徑或全文>
讀者：<誰、要完成什麼>
語域：<技術文章、參考文件、介面文字、工作報告、社群貼文、正式文件之一>
專案文風檔與用詞表：<路徑，沒有就寫「無」>

先讀 zh-tw-prose skill 的 SKILL.md、patterns.md、translationese.md、taiwan-usage.md、
punctuation.md、integrity.md，以及對應語域的檔案。專案有文風檔與用詞表時一併讀。

依影響排序回報：先是讀者任務與事實，其次是結構與重複，最後是句子、用詞與標點。
每個問題一行，格式如下：

<位置（行號或引用原句的前幾個字）> <問題> → <建議寫法>

沒有把握的標「不確定」。需要作者提供事實才能改的，標「待作者補充」。
最後用兩三句說明這份稿件是否服務它的讀者。不稱讚，不重述規則。
```

## 收到回報後

- 逐項判斷，不是每一項都要照改。審稿者不知道的背景，以寫作者掌握的事實為準。
- 改完後只看改過的段落，不需要再請同一位審稿者讀一次全文。
