# 翻譯腔與歐化中文

模型的中文常常是英文句構換上中文字：名詞當主詞、動詞被架空、被動句與代名詞太多。這份清單整理自余光中〈怎樣改進英式中文〉、思果《翻譯研究》的論點，以及在地化指南對 zh-TW 的要求。例句都是自己寫的示範句。

判斷原則：讀起來像翻譯稿，就把句子還原成中文的語序，先說誰、再說做什麼。每個模式都附「保留」，符合保留條件的寫法是對的，不要改。

後例裡的具體內容是為了示範而假設的。實際改稿時只調整句構，原文沒有的事實不要自己補。

## T01 虛動詞加名詞

- 模式：「進行討論」「作出決定」「加以說明」「予以處理」「做出回應」。
- 理由：真正的動作藏在名詞裡，前面再接一個沒有意思的動詞，句子變長，讀者要多繞一步。
- 改法：直接用原本的動詞。
- 前：`我們對這個問題進行了深入的探討。`
- 後：`我們仔細討論了這個問題。`
- 前：`系統會對輸入的資料加以驗證。`
- 後：`系統會驗證輸入的資料。`
- 保留：「做決定」「做筆記」這類口語本來就常用的搭配。正式文件語域的公文用語，見 [registers/formal.md](registers/formal.md)。

## T02 抽象名詞當主詞

- 模式：「效率的提升帶來了成本的降低」「這個設計的實現需要……」。
- 理由：中文習慣讓人或東西當主詞，抽象名詞當主詞時，讀者要先把名詞還原成動作才看得懂。
- 改法：讓人或東西當主詞，動作寫回動詞。
- 前：`效能的改善得益於快取機制的引入。`
- 後：`加上快取後，頁面載入變快了。`
- 保留：標題、表頭與術語本來就用名詞（「效能改善」）。文章在討論那個概念本身時，例如「這次的效能改善來自兩個地方」。

## T03 迴避「是」與「有」

- 模式：「扮演著重要的角色」「作為一個……」「呈現出……的特性」「有著……」「具備……的能力」。
- 理由：避開簡單的「是」與「有」，句子會繞遠路，意思也變模糊。
- 改法：能用「是」「有」「負責」「會」就直接用。
- 前：`這個模組扮演著處理登入流程的角色。`
- 後：`這個模組負責登入。`
- 前：`作為一名開發者，你應該熟悉 Git。`
- 後：`你需要會用 Git 的基本指令。`
- 保留：「作為」表示身分或資格的正式用法，例如公告裡的「作為主辦單位，我們會……」。徵才與規格文件裡的「具備……經驗」是慣用說法。

## T04 不必要的被動句

- 模式：「被系統讀取」「被認為是」「被廣泛使用」這類描述中性動作的被動句。
- 理由：中文的被動多半帶有不幸或被迫的語氣，中性的動作寫成被動，讀起來像翻譯稿，甚至會被讀成有壞事發生。
- 改法：找出動作的主體，改成主動。
- 前：`設定檔會被系統自動讀取。`
- 後：`系統會自動讀取設定檔。`
- 前：`這個設定會被多個服務讀取。`
- 後：`多個服務會讀取這個設定。`
- 保留：不幸或被迫的事，例如「帳號被盜用」「請求被拒絕」。主體不明、又是不希望發生的結果時，例如「資料在轉換過程中被截斷」。

## T05 「的」字堆疊與冗長前飾

- 模式：一個名詞前面掛好幾個「的」，例如「一個能夠有效提升團隊溝通效率的重要的工具」。
- 理由：修飾語都放在名詞前，太長時讀者要記住一大串才看到主角。
- 改法：把修飾語拆成另一句，或改用動詞。
- 前：`這是一個能夠有效減少重複程式碼的實用的工具。`
- 後：`這個工具能減少重複的程式碼。`
- 保留：兩層以內、讀起來順的修飾，例如「未儲存的表單內容」。

## T06 介詞與連接詞過多

- 模式：「關於」「對於」「由於」「通過」「基於」「在……方面」「在……上」「當……的時候」放在句首。
- 理由：中文靠語序與上下文表達關係，句首的介詞片語讓句子變重，主詞也被往後推。
- 改法：能省就省，必要時換成口語的說法。「通過」在台灣是「通過考試」的意思，表示手段時用「透過」或「用」。
- 前：`對於這個錯誤，我們可以通過修改設定的方式來解決。`
- 後：`修改設定就能解決這個錯誤。`
- 前：`當使用者點擊按鈕的時候，系統會送出表單。`
- 後：`按下按鈕後，系統會送出表單。`
- 保留：需要明確點出原因或對象時，「由於」「對於」可以用，正式文件裡也常見。「關於」用在標題或轉換話題時，例如「關於退款」。

## T07 代名詞與「們」過多

- 模式：每句都用「它」「他們」「其」指回前文，或在不需要的地方加「們」（「各位使用者們」）。
- 理由：中文的主詞在上下文清楚時可以省略。代名詞一多，讀者要回頭猜「它」指的是哪一個。
- 改法：省略不需要的代名詞。需要指稱時重複名詞，比「它」清楚。
- 前：`安裝這個套件後，它會在專案中建立一個設定檔，你可以修改它來調整它的行為。`
- 後：`安裝這個套件後，專案裡會多一個設定檔，修改這個檔案就能調整套件的行為。`
- 保留：指涉清楚、重複名詞反而累贅時可以用「它」。「我們」「他們」指的是真實的一群人時。

## T08 數量詞「一個」

- 模式：英文的 a、an 直譯成「一個」，例如「這是一個很好的方法」「建立一個新的檔案」。
- 理由：中文的名詞不分單複數，多數時候不需要數量詞，加了只是英文冠詞的影子。
- 改法：數量不重要時省略。
- 前：`我們需要建立一個新的分支來進行一個測試。`
- 後：`我們要開新分支來測試。`
- 保留：數量本身有意義時，例如「同時只能開一個連線」「每個帳號只能綁定一支手機」。

## T09 「使、讓」的使役句

- 模式：「這使得程式更容易維護」「讓使用者能夠更方便地操作」。
- 理由：「使、讓」把因果藏在抽象的使役結構裡，讀者看不到具體改變了什麼。
- 改法：寫出誰做了什麼。原文沒寫具體改變時，只把句構改直接，或問使用者。
- 前：`這個改動使得程式碼更容易被閱讀。`
- 後：`改完後，程式碼比較好讀。`
- 保留：主體具體，而且確實是它造成後果，例如「這個錯誤讓整個服務停了兩小時」。

## T10 英文語序的長定語與插入語

- 模式：把英文的關係子句整段塞在名詞前面，或用破折號、括號插入一大段補充。
- 理由：中文的定語放在名詞前，英文式的長子句塞進去後，讀者要讀完整串才知道句子在講什麼。
- 改法：先說主要的事，補充另起一句。
- 前：`在你完成了前面提到的那些用來設定環境變數的步驟之後再執行這個指令。`
- 後：`先照前面的步驟設定環境變數，再執行這個指令。`
- 前：`這個參數——如果你使用的是舊版本，而且沒有手動修改過預設值的話——會被忽略。`
- 後：`使用舊版本、又沒有改過預設值時，這個參數不會生效。`
- 保留：短的括號補充，例如英文原名或單位。破折號用來解釋前文時可以用，一句最多一處。
